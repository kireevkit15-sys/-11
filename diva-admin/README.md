# DIVA Admin

Отдельная кастомная админ-панель сайта ДИВА. Управляет контентом из общей БД
(`db/schema.ts`) через динамический CRUD по реестру сущностей.

## Стек

- Next.js 15 (App Router) + React 19
- TypeScript, Tailwind CSS v4
- Drizzle ORM (`postgres-js`) поверх общей схемы `../db/schema.ts`
- Аутентификация: iron-session (зашифрованный httpOnly-cookie) + RBAC + журнал аудита
- Хеширование паролей: `@node-rs/argon2`

## Архитектура

Вся CRUD-часть управляется одним реестром — [`src/lib/entities.ts`](src/lib/entities.ts).
Каждая сущность описывает таблицу, поля формы и колонки списка. Из реестра
питаются:

- динамический API: `src/app/api/[entity]/route.ts` и `…/[id]/route.ts`;
- динамические страницы: `src/app/admin/[entity]/(page|new|[id])`;
- боковое меню и дашборд.

Добавить новую сущность = добавить запись в реестр (отдельные файлы создавать не нужно).

## Запуск (разработка)

```bash
npm install
cp .env.example .env   # заполнить DATABASE_URL и SESSION_SECRET (>=32 символов)
npm run reset-admin admin@diva.ru 'ВашПароль'   # создать/сбросить администратора
npm run dev            # http://localhost:3001
```

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | подключение к PostgreSQL (та же БД, что web/bot) |
| `SESSION_SECRET` | секрет подписи/шифрования сессии, ≥32 символов |
| `ADMIN_PORT` | порт (по умолчанию 3001) |

## Роли

- `admin` — полный доступ + управление и аудит;
- `editor` — чтение/запись/удаление контента;
- `viewer` — только чтение (запись блокируется middleware).

## Известные ограничения

- Очистка необязательного числового/текстового поля «в пусто» при редактировании
  не сбрасывает значение в `null` (пустые поля пропускаются, чтобы не ломать
  NOT NULL-колонки с DEFAULT). При необходимости добавьте флаг `nullable` в поле
  реестра и обработку в `coerceBody` (`src/lib/api-helpers.ts`).
- Управление пользователями админки и просмотр журнала аудита через UI пока не
  реализованы (данные есть в БД: таблицы `admin_users`, `audit_logs`).
